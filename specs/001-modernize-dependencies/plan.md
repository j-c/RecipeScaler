# Implementation Plan: Modernize Dependencies

**Branch**: `001-modernize-dependencies` | **Date**: 2026-02-27 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-modernize-dependencies/spec.md`

## Summary

Upgrade RecipeScaler from Angular 2.3.1 (a 10-year-old brownfield SPA) to
Angular 19.x LTS and all supporting dependencies to currently maintained
versions. The app has no backend — all state is encoded in base64 URL
parameters. The upgrade must preserve all existing recipe URLs and scaling
behaviour exactly. The approach is one Angular major version per commit,
following the official `ng update` migration path, with test gates after
each hop.

## Technical Context

**Language/Version**: TypeScript 2.0.3 → **TypeScript 5.6.x**
**Primary Dependencies**: Angular 2.3.1 → **Angular 19.x**; Angular Material 2.0.0-beta.1 → **Angular Material 19.x**; RxJS 5.0.1 → **RxJS 7.8.x**; Zone.js 0.7.2 → **Zone.js 0.15.x**
**Storage**: N/A — no backend, no database; all state is in base64 URL parameters
**Testing**: Karma 1.2 + Jasmine 2.5 → **Vitest + jsdom** (unit); Protractor 4 → **Playwright** (e2e)
**Target Platform**: Modern browsers (SPA, HTML5 pushState routing)
**Project Type**: Web SPA (single Angular workspace, no backend)
**Performance Goals**: App loads in <3 seconds on standard broadband (SC-006; no regression from upgrade)
**Constraints**: Offline-capable (pure SPA); base64 URL scheme immutable; no backend introduction
**Scale/Scope**: Single developer; personal utility; ~2 components, ~6 models, ~2 view models; ~162 lines of component logic

## Upgrade Phases

The upgrade is split into 9 phases. Each phase ends with the full
verification gate from `quickstart.md`. No phase may begin before the
previous phase passes all gates.

---

### Phase 0: Baseline Stabilisation

**Goal**: Establish a known-good starting point before touching any dependencies.

**Actions**:
1. Record the current toolchain state: document which Node/npm version currently
   builds the app (or document that it does not build on current Node and why).
2. Add `.nvmrc` with the target Node version (`22`).
3. Add `engines` field to `package.json` if not present.
4. Run `npm install` and `ng build` on the oldest supported Node where the project
   compiles. Document the result.
5. Commit: `chore: record baseline toolchain (Node version, .nvmrc)`

**Gate**: Project state is documented. Does NOT need to build on current Node yet
(it almost certainly will not — the goal is a recorded baseline, not a passing build).

---

### Phase 1: Node Runtime + Initial Dependency Audit

**Goal**: Move to Node 22 LTS. Remove obviously blocked package versions.
Install `rxjs-compat` bridge early.

**Actions**:
1. Switch to Node 22 LTS (via `nvm use 22` or equivalent).
2. Attempt `npm install`. Expect failure — angular-cli 1.x is incompatible with
   Node 22. This is the known starting condition. Note all errors.
3. As a preparatory step (not yet upgrading Angular), install the minimum Node
   version at which `angular-cli@1.0.0-beta.28.3` and Angular 2.3.1 can build.
   This is likely Node 8 or 10 (the era-appropriate version).
4. Document the minimum buildable Node version in `research.md` upgrade notes.

**Note**: Phase 1 establishes the floor. The Angular CLI version must be upgraded
before Node 22 will work. The full Node 22 target is achieved at Phase 3 (Angular 6+).

**Commit**: `chore: baseline — document Node compatibility floor`

---

### Phase 2: Angular 2 → 6 (CLI Config Migration + RxJS 6)

*This phase covers the highest-density of structural changes. Each hop is a
separate commit.*

#### 2a. Angular 2 → 4
```bash
ng update @angular/cli@4 @angular/core@4
```
- Fix any template type errors surfaced by stricter type checking.
- Note: `@angular/http` still present and usable.
- Commit: `chore: upgrade Angular 2→4`

#### 2b. Angular 4 → 5
```bash
ng update @angular/cli@5 @angular/core@5
```
- Migrate `HttpModule` + `Http` → `HttpClientModule` + `HttpClient` in `AppModule`
  (see data-model.md notes — may be unused; verify first).
- Commit: `chore: upgrade Angular 4→5; migrate @angular/http → HttpClient`

#### 2c. Angular 5 → 6 (Config Migration + RxJS)
```bash
ng update @angular/cli@6 @angular/core@6
```
- `ng update` **automatically** converts `angular-cli.json` → `angular.json`.
- Install `rxjs@6` + `rxjs-compat@6`:
  ```bash
  npm install rxjs@6 rxjs-compat@6
  ```
- Run `rxjs-5-to-6-migrate` (from `rxjs-tslint`) as a first-pass rewrite:
  ```bash
  npm install -g rxjs-tslint
  rxjs-5-to-6-migrate -p src/tsconfig.json
  ```
  Review and commit all changes from the migration tool.
- Remove `ts-helpers`: `npm uninstall ts-helpers`
- Commit: `chore: upgrade Angular 5→6; migrate angular-cli.json→angular.json; rxjs 5→6 with compat`

**Gate after Phase 2**: `npm install && ng build && ng serve` must pass.

### Phase 3: Angular 6 → 9 (Ivy + Remove @angular/http)

#### 3a. Angular 6 → 7

- Commit: `chore: upgrade Angular 6→7`

#### 3b. Angular 7 → 8
```bash

```

- Commit: `chore: upgrade Angular 7→8`

#### 3c. Angular 8 → 9 (Ivy default; `@angular/http` removed)
```bash

```
- **BLOCKER**: `@angular/http` is removed at v9. Must have completed migration
  to `HttpClientModule` in Phase 2b. If any remaining usages exist, fix them now.
- Ivy is now default. Fix all template type errors surfaced by stricter Ivy
  template type-checking.
- Drop `rxjs-compat` now that all imports are rewritten:
  ```bash
  npm uninstall rxjs-compat
  ```
- Update `polyfills.ts` zone.js import path if already past zone.js 0.14:
  ```ts
  // Change: import 'zone.js/dist/zone'
  // To:     import 'zone.js'
  ```
- Commit: `chore: upgrade Angular 8→9; remove @angular/http; drop rxjs-compat; Ivy default`

**Gate after Phase 3**: All three gates (install, build, serve) must pass under Node 12+.
Angular 9+ supports Node 12; the project can now move to a more recent Node.

### Phase 5: Angular 13 → 15 (Angular Material MDC Rebuild)

This is the most visually disruptive phase. Angular Material v15 rebuilds
all components on MDC. Expect CSS class changes and DOM structure changes.
NFR-001 (loose visual parity) applies — do not spend time recreating exact
pixel styling.

#### 5a. Angular 13 → 14
```bash
ng update @angular/cli@14 @angular/core@14 @angular/material@14 @angular/cdk@14
```
- TypeScript 4.6+ required.
- Fix any `FormControl<T>` type errors (typed reactive forms).
- Commit: `chore: upgrade Angular 13→14`

#### 5b. Angular 14 → 15 (MDC rebuild)
```bash
ng update @angular/cli@15 @angular/core@15 @angular/material@15 @angular/cdk@15
```
- `ng update` runs migration schematics: migrates material component imports
  from legacy to MDC variants.
- **At this hop**: Remove `bootstrap-material-design`, Bootstrap 3 CDN, Font
  Awesome 4 CDN, and `ng2-sharebuttons`:
  ```bash
  npm uninstall bootstrap-material-design ng2-sharebuttons
  ```
  Remove from `index.html`:
  - Bootstrap 3 `<link>` (CDN)
  - Font Awesome 4 `<link>` (CDN)
  Remove from `styles.css`:
  - `@import '~bootstrap-material-design/...'` lines
  Remove from `app.module.ts`:
  - `ShareButtonsModule` import
  Remove from `recipe.component.html`:
  - `<share-buttons>` element
  Replace any Font Awesome icon usages with Angular Material icons (`mat-icon`).
- Apply the new Angular Material M2 SCSS theming in `styles.scss`:
  ```scss
  @use '@angular/material' as mat;
  @include mat.core();
  $app-primary: mat.define-palette(mat.$indigo-palette);
  $app-accent:  mat.define-palette(mat.$pink-palette, A200, A100, A400);
  $app-theme:   mat.define-light-theme((
    color: (primary: $app-primary, accent: $app-accent)
  ));
  @include mat.all-component-themes($app-theme);
  ```
  _(This M2 SCSS will be replaced by the `mat.theme()` API at v19; use
  `ng update` migration to auto-convert.)_
- Verify layout intent is preserved per NFR-001.
- Commit: `chore: upgrade Angular 14→15; MDC material; remove Bootstrap/FontAwesome/sharebuttons`

**Gate after Phase 5**: install + build + serve + recipe URL visual check.

- Commit: `chore: upgrade Angular 18→19; mat.theme() theming API`

**Gate after Phase 6**: Full gate sequence — install, build, serve, recipe URL.

### Phase 7: Test Tooling Migration

**Timing**: This phase can begin any time after Phase 4 (Angular 13) and must
be complete before the 18→19 hop (Protractor builder removed at v19).

#### 7a. Remove Protractor; Add Playwright
```bash
npm uninstall protractor
ng add playwright-ng-schematics
```
- Delete `e2e/` directory and `protractor.conf.js`.
- Playwright schematic scaffolds `playwright/` with Angular-aware configuration.
- Write the required smoke tests per FR-018:
  ```ts
  // playwright/smoke.spec.ts
  test('app loads default recipe', async ({ page }) => { ... });
  test('recipe URL renders expected recipe', async ({ page }) => { ... });
  ```
- Commit: `chore: replace Protractor with Playwright; add recipe URL smoke test`

#### 7b. Migrate Karma → Vitest
```bash
npm uninstall karma karma-chrome-launcher karma-jasmine karma-jasmine-html-reporter \
             karma-remap-istanbul karma-cli jasmine-core jasmine-spec-reporter \
             @types/jasmine
npm install --save-dev vitest jsdom
```
Update `angular.json` test target builder:
```json
{
  "test": {
    "builder": "@angular/build:unit-test"
  }
}
```
Delete `karma.conf.js` and `src/test.ts`.

Run the migration schematic:
```bash
ng g @schematics/angular:refactor-jasmine-vitest
```
Review output. Manually fix any `fakeAsync`/`flush` usages (rewrite using
`async/await` + `vi.useFakeTimers()`). Ensure at least one test exercises
recipe scaling logic (SC-004, US3 acceptance scenario 2).

- Commit: `chore: replace Karma/Jasmine with Vitest`

### Phase 8: Final Validation & Housekeeping

**Actions**:
1. Run full quickstart.md gate sequence from a clean `node_modules`.
2. Validate recipe URL smoke test passes (SC-003, SC-008).
3. Run `npm audit` and resolve any high/critical severity vulnerabilities (SC-005).
4. Run `ng update` and confirm no pending updates remain.
5. Update `README.md` with current scripts, Node version, and build instructions.
6. Pin Node version in `package.json` `engines` field and confirm `.nvmrc` exists.
7. Record the "Upgrade Notes" per Constitution Development Workflow (new version

8. Commit: `chore: modernize dependencies — Angular 19 LTS; update README`
